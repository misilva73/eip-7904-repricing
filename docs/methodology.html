Methodology

Benchmark data

Runtimes are pulled from the Benchmarkoor API by benchmarkoor-fetch, pinned to two jochennet suite hashes for reproducibility:

  • 3182dda7b93dee61
  • a11611f320a39015

The benchmarks ran on the amsterdam fork; runs are selected by the .*-full.* run-id pattern. The compute suite drives the target-opcode fits, while the stateful suite feeds the glue-opcode analysis.

Gas-cost baseline

Proposed values are compared against the osaka gas-cost table — distinct from the amsterdam fork the benchmarks ran on. The osaka table is the intended cost baseline for the EIP-7904 proposal.

Regression model

Each fit is a non-negative least squares (NNLS) regression of test runtime against opcode count, with bootstrap inference (1000 iterations). The target coefficient is the per-unit runtime of the opcode under study. Variable-cost opcodes (MOD/SMOD/ADDMOD/MULMOD by bit-width, KECCAK256 base + per-word, several precompiles) are modelled with their own fixture parameters; constant-cost opcodes (DIV, SDIV) use a single coefficient.

Fits cover 5 clients:

  • besu
  • erigon
  • geth
  • nethermind
  • reth

Anchor & worst-case selection

Each opcode's measured runtime is converted to gas at an anchor rate of 100,000,000 gas/s (100 Mgas/s) — any op running slower than this anchor is flagged for a bump. For every gas parameter the proposal takes the worst-case across clients: the highest per-client gas value, so the cost holds on the slowest client. The client comparison shows how far the worst client sits from the rest of the field.

Glue adjustment

Glue adjustment is enabled. When enabled, the runtime attributed to a target opcode is netted against the runtimes of the priced "glue" opcodes that surround it in the benchmark fixtures (loads, pushes, dups, control flow). A glue fit is only subtracted when it passes its p-value (< 0.05) and R² (≥ 0.5) thresholds; skipped fits are listed under Warnings. See the glue page for the per-fit detail.

Filters

All exclusions are expressed in configuration rather than a pre-processing step. The ethrex client is dropped by omission from the client list; per-op fixture exclusions (e.g. bn128_add_infinities, the test_arithmetic selection for the modular opcodes) ride along inside each preset's built-in selectors.

Reproducibility

Re-run the full pipeline end to end:

make fetch     # → data/raw/    (needs a Benchmarkoor token in secrets.json)
make gasfit    # → data/gasfit/
make site      # renders this site into site/

The committed data/ directory makes the published site self-contained: every figure and table on these pages traces back to those artifacts.
